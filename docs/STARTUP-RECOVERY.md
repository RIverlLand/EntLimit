# 登录自启检查与紧急关闭

## 不用反复重启的自启验证

当前自启方式是当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\EntLimit`，登录 Windows 时启动监控，不打开主界面。

2026-10-18 完成了以下检查：

- 临时通过正式配置接口注册这台电脑的真实启动项，核验完整 EXE 和数据目录命令；测试结束恢复原来的配置和注册值。
- 执行真实注册参数，已有监控保持单实例，未改动许可或学习记录。
- 在独立实例中，用 Windows `CreateProcessW` 执行同格式的完整启动命令，模拟冷启动；工作目录故意设在其他位置，数据路径含空格和末尾反斜杠，继承的环境数据目录也故意设错。
- 确认参数指定的配置被加载、不出现主界面、重复启动不产生多实例，启用的守护能随之运行。

这些检查验证注册、命令解析、配置定位与后台生命周期，不等于模拟了整个 Windows 登录。Windows 设置/任务管理器禁用启动项、组织策略、登录环境等仍属于系统触发边界。无需为此反复关机；下次自然登录后确认托盘出现即可。测试不会替你长期开启自启；使用时在规则页勾选后保存。

## 出问题时怎么关闭

首选双击项目根目录或完整发布目录中的 **`EmergencyStop.cmd`**。正式发布位置为 `artifacts/app/EmergencyStop.cmd`，配套脚本必须与它一起保留。

它在独立 PowerShell 窗口执行，不依赖主界面、监控 IPC 或配置 JSON 能否读取：

1. 在该数据目录创建 `emergency-stop.flag`，作为持续生效的紧急停用标记。
2. 移除与本安装 EXE、数据目录完整匹配的登录自启项，保留其他安装的项。
3. 仅关闭本安装路径、当前 Windows 会话中的 EntLimit 监控、守护和主界面，不关闭游戏、浏览器或其他软件。
4. 保留配置、学习记录和草稿文件；强制结束进程前尚未保存的操作可能丢失。

守护看到标记后不再拉起监控。重新手动打开主界面仍保持紧急暂停；到“规则与网站 → 调试入口”，点击 **“解除紧急停用并恢复管控”** 才会恢复。恢复后自启和守护保持关闭，可以另行勾选。旧许可保留原时间，不重新发放 90 分钟。

网站扩展在下次同步时清掉拦截规则，最多约一分钟，也可手动同步；已经跳转到的学习入口要重新导航回目标网站。即使监控离线、配置损坏，桥接也可读取紧急标记返回暂停。

界面能操作时仍可使用原来的普通“一键停用”与“停用并退出”。紧急关闭用于普通出口卡住的情况；它是明确可见的本地逃生入口，没有远程入口或秘密密码。

如果独立脚本被系统策略阻止，可以手动在 `artifacts/app/data` 创建名为 `emergency-stop.flag` 的文件，再用任务管理器结束 EntLimit 监控和界面。自定义数据目录应使用自己的实际目录。
